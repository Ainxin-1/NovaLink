一、架构决策
------------------------------------------------------------------------
选择 "Go 后端 + 内嵌 Web 界面" 而非原生 GUI 框架：
- 本机无 GUI 工具链（无 node/wails 前端链、无 gcc/Fyne），Web 方案
  纯 Go 标准库即可完成并可当天实测
- 界面即网页：首页/节点列表/设置/日志四页结构可直接移植到
  Android（WebView + libbox），两端 UI 行为一致（任务书第三十三章）
- 后续如需桌面原生外壳，可加 WebView2 启动器，不影响后端

代码结构：
client/
├─ main.go          服务与全部 API（status/nodes/connect/disconnect/
│                   check/settings/log），go:embed 界面
├─ core/settings.go 设置持久化（data/settings.json，首次运行生成默认值）
├─ core/core.go     核心生命周期：生成配置→校验→启动子进程→异步验证→
│                   健康监控→停止（含进程树击杀与端口预检）
└─ web/index.html   四页界面（深色主题，无外部资源，可离线）

复用管线模块：novanode/model（节点结构）、novanode/publish.Outbound
（单节点出站生成）、novanode/checker.TCP（设备端检测）、
novanode/cache.Load（读池）。客户端只读节点池，不写管线数据。

三、实测发现并修复的真实缺陷（GUI 实测价值所在）
------------------------------------------------------------------------
1. 连接健康监控缺失（最重要）：
   首次连接成功后约 2 分钟节点死亡，界面仍显示"已连接"。
   -> 新增：已连接状态每 20 秒健康检查，连续 2 次失败自动断开并
      提示"连接已失效，请更换节点后重试"（任务书第十七章）
2. 残留核心进程占用端口：
   强杀客户端父进程后 sing-box 子进程残留，7890 被占导致下次连接
   核心启动即退。
   -> 新增：连接前端口预检（快速失败并给出明确提示）+
      停止时 taskkill /T 结束整棵进程树
3. 手动断开时进程退出监控误报"异常退出"：状态置位顺序修正
4. UI 缺陷：状态列显示 undefined（字段大小写）、首页池统计不加载

六、追加迭代（2026-09-12 晚，用户实测反馈驱动）
------------------------------------------------------------------------
用户反馈"YouTube 访问不了"，诊断出两个根因并全部修复：

1. [新增] 系统代理自动接管（根因一）：
   v0.1 只开本地端口 7890，不接管 Windows 系统代理，
   浏览器流量根本不经过 NovaLink。
   -> 连接成功后自动写入系统代理（注册表 ProxyEnable/ProxyServer/
      ProxyOverride），并通过 InternetSetOption 通知刷新；
      设置前先备份用户原代理配置（sysproxy_backup.json），
      断开/失败时自动恢复原状（不破坏 v2rayN 等其他客户端配置）。
   -> 注册表实测：ProxyEnable=0x1, ProxyServer=127.0.0.1:7890 正确写入，
      失败/断开后正确恢复。设置页新增开关（默认开）。

2. [新增] 失败自动换节点（根因二：免费节点秒死）：
   严格实测：连续 13 个"TCP 可用"节点无一能在连接后 10 秒存活，
   全部 502（协议死）/400（端口被 nginx 劫持）。
   -> 重写核心管理为 supervise 监督者模型（任务书第十五章 v1）：
      连接验证失败 / 健康检查连续 2 次失败 / 核心进程异常退出，
      均自动切换下一个候选节点（最多连续 5 个），全程日志可见；
      候选耗尽才显示"连接失败"。
   -> 完整轮换实测通过：6 个候选逐个尝试（每个约 26 秒），
      耗尽后进入 failed 并给出友好提示，系统代理正确恢复。

3. [修复] 生命周期代际 bug（自动换节点首版失效）：
   Connect 传入 gen=m.gen+1 但未存回，监督者首轮即被代际检查
   误判退出，表现为永远"连接中"。经 pprof 协程栈定位后修复。
   （教训：静默失败的 goroutine 必须有入口日志）

4. 当日免费节点结论：20:42 管线刷新节点池后重试，6 候选仍全部失败
   —— 今日该网络下这批免费来源的节点质量为"整体不可用"。
   客户端与管线的机制全部验证正确；可用性问题归因于数据源本身，
   解法是任务书既定路线：管线部署 GitHub Actions 小时级更新 +
   镜像分发 + 阶段 5 协议级设备端检测 + 更多来源。
